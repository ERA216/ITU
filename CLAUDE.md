# Чистый счёт — контекст проекта для Claude Code

Проект для V Регионального ITU Hackathon-2026, FinTech-кейс спонсора **Банк ЦентрКредит (БЦК)**.
Сдача решения: **до 20 ноября 2026**. Финал: 4 декабря 2026. Приз: 1 000 000 ₸.
Автор и единственный технический участник команды: ERA (GitHub ERA216). Общаемся **на русском**, коротко и по делу.

Полная история решений, исследований, ревизий и чисел: @docs/HISTORY.md
Запуск, сценарий показа, персонажи и защита: `README.md`.

## Идея в одном абзаце

Защищаем честных клиентов от статуса дроппера. Если клиенту пришли чужие деньги, приложение сразу предупреждает и даёт вернуть их отправителю одной кнопкой. Если мошенник уговаривает переслать деньги дальше («ошибочный перевод»), перевод останавливается. Если пострадавший жалуется, система идёт по цепочке переводов и приостанавливает счета. Невольный участник подаёт апелляцию прямо в приложении, со сроком ответа. Сотрудник банка видит цепочку, подсказку «невольный участник или организатор» и принимает решение. Вокруг этого: списки Антифрод-центра, сигнал оператора о звонке, доверенное лицо, предупреждение о вербовке, справка о снятии ограничений, проверка подозрительного сообщения, период охлаждения, панель эффективности.

## Правила пользователя (соблюдать всегда)

- **Где есть выбор между вариантами, выбирать тот, что выгоднее банку** (безопаснее для денег, меньше ложных остановок, меньше нагрузки на сотрудников).
- Хостинг делаем только в последние дни перед сдачей. Dockerfile готов, но образ ни разу не собирался.
- Презентацию и видео пользователь пока отложил: сейчас только проект.
- Работаем по задачам, которые дал пользователь. Новые функции предлагать списком и ждать выбора, не делать без спроса.
- Тексты для клиента: простым языком, на «вы», без канцелярита; всё на русском и казахском.
- Не обещать в текстах юридических последствий, которые не проверены (например, банк НЕ может сам исключить клиента из базы Антифрод-центра).

## Команды

```bash
pip install -r requirements.txt
uvicorn app.main:app --reload          # http://127.0.0.1:8000/ (клиент), /analyst (код 2026), /analyst/stats, /quality
python -m pytest -q                    # 71 тест, ~18 с; каждый тест на своей копии базы
python -m app.quality                  # пересчитать app/static/quality.json (10 наборов данных, несколько минут)
```

Первый запуск сервера ~10 с: создаются демо-данные и история за 30 дней (`CA_DEMO_HISTORY=1`).

Переменные окружения: `CA_DB`, `CA_UPLOADS`, `CA_DOC_KEY` / `CA_DOC_KEY_FILE`, `CA_ANALYST_PIN` (по умолчанию 2026), `CA_DEMO_HISTORY` (1/0), `CA_TZ` (Asia/Almaty), `CA_COOLING_MINUTES` (60), `CA_PUBLIC=1` (хостинг: без PIN код случайный), `CA_HTTPS=1` (secure-куки), `PORT`.

## Устройство

- `app/main.py` — весь API (FastAPI). Один запрос = одна транзакция (зависимость `tx()` с замком; в ней же `_settle_due()` проводит переводы, у которых закончился период охлаждения).
- `app/engine.py` — правила перехвата. Каждый признак = баллы + текст причины. Порог 85, если на счёте есть «чужие» деньги; 60 без них (звонок, серый список, опасное сообщение). Окно 120 ч. Также `assess_role` (подсказка сотруднику), `recruitment_signal`, `find_forward`.
- `app/messages.py` — распознавание схем в тексте сообщения (правила ru+kk).
- `app/seed.py` — синтетика (300 клиентов, 90 дней) и демо-персонажи 1001–1010. `app/history.py` — смоделированная история случаев за 30 дней.
- `app/metrics.py` — панель эффективности и связанные счета. `app/quality.py` — качество движка.
- `app/i18n.py` — тексты сервера ru/kk (`t(key)`), казахские имена персонажей, причины по коду.
- `app/db.py` — схема SQLite; `SCHEMA_VERSION` (сейчас 8): старая база удаляется и создаётся заново.
- `app/vault.py` — шифрование документов (Fernet). `app/clock.py` — время Казахстана.
- `app/static/index.html` — экран клиента (тексты в объекте `T`, ru/kk). `analyst.html`, `stats.html`, `quality.html`.
- `tests/test_flow.py` — сквозные тесты.

## Как вносить изменения (сложилось за проект)

- Меняешь схему базы → подними `db.SCHEMA_VERSION` и добавь новую таблицу в список очистки в `seed.populate(reset=True)`.
- Деньги двигаются только через `_move`; резерв = переводы со статусом `held` и `pending` (`_held_sum`). Каждое действие по случаю — `log(...)`.
- Любой новый текст для клиента — в `i18n.MSG` (сервер) или в `T` в `index.html`, сразу на двух языках. Казахский потом вычитывает носитель.
- На каждую функцию и каждую исправленную ошибку — тест в `tests/test_flow.py` (сначала воспроизвести, потом чинить).
- Поменял движок → `python -m app.quality` и обнови цифры в README (сейчас: ловит 88%, ложных остановок 0,20%).
- После правок экранов — проверка в браузере (Playwright, ширина телефона 400 px, без горизонтальной прокрутки, без ошибок на странице).
- Обнови `README.md` (сценарий показа, «Как защищены деньги и данные») и `docs/HISTORY.md`.
- Коммиты на русском, одной строкой суть + список изменений.

## Подводные камни

- Индекс по `transfers(status)` ломает план запросов и вдвое замедляет движок; для отложенных переводов — частичный индекс `ix_tr_pending`.
- Имена синтетических клиентов («Данияр О.», «Руслан А.») совпадают с персонажами: в тестах и браузерных проверках искать по «Данияр (продаёт», «Руслан (счёту».
- Даты хранятся как наивное местное время Алматы (ISO-строки); сравнения строковые.
- Демо-данные старше 48 ч пересоздаются сами при запросе `/demo/clients`.
- Тесты ставят `CA_DEMO_HISTORY=0` и `CA_ANALYST_PIN=4321`.
